Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's Algorithm

De Casteljau's algorithm is a way to compute a Bezier curve by recursively interpolating along the lines between control points of the Bezier curve. It takes a parameter t that describes how far along each line to interpolate, then recursively iterates until a single point is left, which is the point on the curve represented at parameter t. Using multiple different parameters t, the algorithm can approximate the curve.

Implementation

To implement the algorithm (or one recursive call of it), I interpolate along the line between 2 control points by weighting each dimension's coordinate from each control point, then adding them together to get each dimension's coordinate of the interpolated point. The first point's coordinates are weighted by (1-t), since the lower t is, the closer it is to the first point, so the more weight I want the first point's coordinates to have.

I apply this to each set of 2 consecutive control points in array points by iterating through the array, and appending each new control point to an array control_points. Once I finish iterating, I return the array control_points.

Part 2: Bezier surfaces with separable 1D de Casteljau

Extending De Casteljau's to Bezier Surfaces

A Bezier surface is just a NxM grid, so it can be represented as N 2d Bezier curves. De Casteljau can thus be extended to Bezier surfaces by calculating the final point on each of N 2D Bezier curves, then treating those M points as control points for a Bezier curve going in the third dimension. This takes parameters u and v describing how far along each line between control points to interpolate, u for the 2D Bezier curve interpolation, then v for the 3D interpolation.

Implementation

To implement this, I first filled in the function evaluateStep, which is the same as Task 1, but just interpolates along 3 dimensions instead of 2. All that changed is another line to interpolate along the z axis.

Then I filled in evalulate1D, which recursively calls the part 1 evalulateStep on the array of control points points using parameter t until I am left with a single point, which is the point on the Bezier curve represented at t.

Finally, I filled in the function evaluate, which takes the control point array from the BezierPatch object calling it. controlPoints is an array of arrays of 3D Vectors, so iterating over the outer array will give an inner array of 3d control points along each "slice" of the Bezier surface. This is then passed to evaluate1D along with parameter u, which gives the final point along the curve represented at u. Each of these final points is then treated as a Bezier curve in the third dimension and interpolated at parameter v using evaluate1D again, which gives the final point for the surface.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

Implementation

I implemented the area weighted vertex normals in a couple steps. The first step is to calculate the normal of each incidental triangle that is connected to the vertex. A normal can be calculated using the cross product of two vectors that share a vertex on the triangle.

To get 2 vectors that share the original vertex, I need the other two vertices of each triangle, which can be found by getting each halfedge inside the triangle that runs toward the original vertex. If the original vertex is A and the other two are B and C, I need BA, and CA. The halfedge in the vertex will be AB, so I take the ->twin() of that halfedge() to get BA. BA->next() will give me AC, so I take the twin() of that to get CA. I then take the vertex() of each of these halfedges, and by subtracting the coordinates of vertex A from them, I get the vector of BA and CA. The cross product of these two vectors then gives me the normal for that triangle.

To get to the next triangle, I can first see that it shares an edge with the triangle I just calculated the normal of. Going clockwise, it is edge AC, which is the ->next() halfedge after BA. I can then use the previous steps to calculate the normal of the new triangle.

To get the unit normal of the vertex, I need to take the area-weighted average of the normals and then normalizing. This is already implemented for me in Vertex.unit(), so I just sum up the normals of neighboring triangles and pass it to unit().

For u, as according to the spec, if there are 3 edges from the vertex, u is 3/16; else, it is 3/(8*n).

I also set each original vertex on loop iteration that I'm starting from as ->isNew=false (since I've seen it before). I then calculate the positions of each neighbor along with the original vertex, then calculate the new position by weighting the neighbors against the original vertex using (1 - n * u) * original_position + u * original_neighbor_position_sum.

Observations

Sharp edges tend to start rounding out after loop subdivision, but the corners stay sharp - in fact, they become even sharper as the associated edges round out. Multiple recursions in, localized peaks also start to form on the surface mesh, and the mesh also becomes somewhat asymmetric. Pre-splitting edges seems to introduce additional peaks, but makes the corner a little smoother. On meshes with more even edges, this effect is drastically reduced - it smooths out the overall mesh without introducing large localized peaks (they still exist though). I imagine this is because since each vertex and edge has more neighbors in each direction, they cannot be sharply pulled in one direction while updating the position.

More Cube Observations

The cube becomes asymmetric after subdividing. I think this is because the initial cube has edges only running in one direction on each cube face, weighting the position updates in each subdivision loop in that direction. Pre-processing the cube to provide even edges along each cube face fixes this by providing even directional weight for each update, causing it to subdivide symmetrically.
